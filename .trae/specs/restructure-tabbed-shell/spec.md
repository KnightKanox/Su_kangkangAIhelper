# 康康食养AI 三 Tab 信息架构与结构化推荐 Spec

## Why
现有 A 线是「问候 → 问卷 → 画像 → 推荐」单线四屏：没有首页，老人启动后只能被动答题；推荐结果是一整段 AI 文本，菜名、食材、做法、理由混在一起，难以扫读。B 线演示中的「首页 / 食养 / 我的」三 Tab、画像卡与菜谱卡更符合移动端习惯。本次以 A 线逻辑为主干，吸收 B 线的信息架构与卡片表达，且不改变任何体质、节气、菜谱筛选口径。

## What Changes
- Android 引入三 Tab 外壳：**首页 / 食养 / 我的**（底部导航，文字 + 选中指示条，不新增图标依赖）。问卷与画像保留为全屏二级页，推荐并入「食养」Tab（不再单列推荐屏）。
- 首页：固定问候语卡（完整展示原问候文案）、今日节气、主 CTA（按状态切换）、体质结果卡（已有结果时）、推荐预览（已有推荐时显示第一道，点击跳「食养」）。
- 食养：当前节气胶囊（沿用）+ 3 张**结构化菜谱卡**（菜名 / 菜系 / 主料 / 做法摘要 / 推荐理由 / 忌口提示 / 食养参考标签），支持卡内「展开更多」；补齐「未完成问卷」「无推荐结果」「加载失败」三种状态。
- 我的：体质结果卡、画像摘要（可折叠，Markdown 渲染）、问卷信息摘要（年龄段 / 偏好 / 忌口）、重新填写问卷、查看完整画像。
- 推荐卡数据以本地 CSV 为事实来源；**DeepSeek 只生成每道菜的推荐理由**（按菜名匹配回填）。理由缺失或调用失败时使用本地确定性理由，卡片与主流程不受影响。
- 免责声明「本推荐为食养参考，不构成医疗建议」固定展示，不依赖模型输出。
- Windows 端同步三 Tab 结构（顶部导航）与同字段菜谱卡、同 CTA 规则；业务规则与 Android 完全一致。
- 版本：Android `versionName 1.2.0`、`versionCode 3`；Windows 无版本字段，产物名不变。
- **BREAKING**：移除独立问候屏（问候语改在首页完整展示）；推荐不再以「一整段 Markdown 正文」为主呈现，改为卡片 + 固定免责声明。

## Impact
- Affected specs: 问候、体质问卷采集、健康画像摘要、画像确认与重新开始、节气确定、节气菜谱推荐、生成文案排版、适老可读性。
- Affected code:
  - `android-app/.../ui/AppViewModel.kt`：新增 `Tab` 状态、Tab 切换、理由映射、首页/食养/我的所需派生状态；**不修改体质计算与筛选调用**。
  - `android-app/.../ui/AppRoot.kt`：改为 Tab 外壳 + 二级全屏页。
  - `android-app/.../ui/Components.kt`：新增 `BottomTabBar`、`RecipeCard`、`EmptyState`、`ProfileCard`。
  - 新增 `ui/HomeScreen.kt`、`ui/FoodScreen.kt`、`ui/ProfileScreen.kt`（页面拆分，避免 AppRoot 继续膨胀）。
  - `android-app/.../ui/MarkdownText.kt`：仅供画像摘要使用（推荐理由为纯文本，不渲染 Markdown）。
  - `android-app/app/build.gradle.kts`：仅版本号。
  - `windows-app/app.py`：三 Tab 导航、首页/食养/我的布局、卡片化推荐；`windows-app/logic.py` 仅允许新增「推荐理由生成/解析」辅助函数，筛选与体质逻辑不变。
- 不修改：`recipes.csv`（主表与两份运行时副本）、`ConstitutionCalculator.kt`、`RecommendationEngine.kt`、`SolarTerms.kt`、`DeepSeekClient.kt`、问卷题目与选项、节气表、忌口筛选规则。

## 视觉与交互约束（沿用 v1.1.0 令牌）
- 色板不变：宣纸底 `#F7F2E7`、卡片 `#FFFDF7`、赭橙 `#B3541E` / `#F4E4D4`、墨绿 `#4E6E58` / `#E7EFE7`、墨色 `#3A3226`、辅助 `#74685A`、弱化 `#8C8275`、描边 `#E4D9C3`。
- 底部 Tab：高 64（Android）/ 56 以上（Windows），选中项主色文字 + 3dp 主色指示条，未选 `#74685A`；Tab 只切换内容，不清空问卷与推荐状态。
- 卡片：圆角 16、描边 1dp、内边距 16；菜谱卡字段行用 18sp，菜名 22sp Serif 加粗。
- 适老底线：正文 ≥18sp、可点高度 ≥56、正文对比度 ≥7:1，所有页面可滚动，Tab 不遮挡内容（`safeDrawingPadding`）。

## ADDED Requirements

### Requirement: 三 Tab 信息架构
系统 SHALL 提供「首页 / 食养 / 我的」三个一级 Tab；Android 使用底部导航，Windows 使用顶部导航。Tab 切换 MUST NOT 清空已填答案、体质结果、节气选择或推荐结果。问卷页与画像页作为二级全屏页展示，进入时隐藏 Tab 栏并提供返回。

#### Scenario: 切换后状态保留
- **WHEN** 用户填完问卷、在「食养」查看推荐后切到「我的」再切回「食养」
- **THEN** 节气选择与 3 道推荐仍在，不重新请求、不重置问卷

#### Scenario: 二级页返回
- **WHEN** 用户在问卷页点「返回」
- **THEN** 回到进入前的 Tab，已选答案保留

### Requirement: 首页
首页 SHALL 自上而下展示：品牌字标、固定问候语卡（与既有问候文案逐字一致）、今日节气、主 CTA、体质结果卡（有结果时）、推荐预览（有推荐时）。

主 CTA 规则：
- 未完成问卷 → 「开始健康问卷」；
- 已生成体质但未确认 → 「继续查看健康画像」；
- 已确认并有推荐 → 「查看今日推荐」（跳转食养 Tab）。

推荐预览 SHALL 仅展示第一道菜的菜名、菜系与一句推荐理由；点击跳转「食养」Tab。

#### Scenario: 首次启动
- **WHEN** 应用首次进入
- **THEN** 首页完整展示原问候语，主按钮为「开始健康问卷」

#### Scenario: 已有结果
- **WHEN** 用户在本次会话中已完成推荐后回到首页
- **THEN** 展示体质卡与第一道菜预览，主按钮为「查看今日推荐」

### Requirement: 结构化菜谱卡
每道推荐菜 SHALL 以独立卡片呈现：菜名、菜系、主料、做法摘要、推荐理由、忌口提示（CSV 有内容时展示，为空则不展示该行）、「食养参考」标签。做法摘要默认截断为 1–2 行，卡内「展开更多」展示完整做法与食养特点，再次点击收起。卡片 MUST NOT 出现原始 Markdown 标记。

#### Scenario: 展开更多
- **WHEN** 用户点某张卡片的「展开更多」
- **THEN** 该卡展示完整做法与食养特点，其余卡片保持收起

#### Scenario: 忌口提示
- **WHEN** 某道菜的「忌口提示」字段为空
- **THEN** 卡片不显示该行，不生成「无忌口」等编造文案

### Requirement: 推荐理由生成与回退
系统 SHALL 以本地 CSV 为事实来源渲染卡片；DeepSeek 仅生成每道菜的一句推荐理由（≤40 字，不得编造未出现的食材或功效）。

- 请求格式：一次调用，要求按 `序号. 菜名｜理由` 输出 3 行；
- 解析：按菜名匹配到对应卡片，未匹配到的卡片使用本地理由；
- 本地理由：由「节气 + 该菜 `healthFeatures` 首句 + 体质」拼成，不新增医疗表述；
- 调用失败 / 超时 / 解析失败：全部卡片使用本地理由，流程不阻塞。

#### Scenario: AI 理由正常
- **WHEN** DeepSeek 返回 3 行「菜名｜理由」
- **THEN** 三张卡片分别显示匹配到的理由

#### Scenario: 离线或解析失败
- **WHEN** 无网络或返回内容无法按菜名匹配
- **THEN** 卡片仍完整显示（含本地理由），并保留固定免责声明

### Requirement: 食养空态与异常态
- 未完成问卷：SHALL 显示说明与「去填写问卷」按钮，不得展示示例或伪造菜谱。
- 已确认但筛选结果为空：SHALL 显示「当前节气与忌口条件下暂无合适菜谱」，并提供「切换节气」「重新填写问卷」入口。
- 加载中：显示加载提示；加载失败（含本地筛选异常）：显示可重试的提示与「重新加载」。

#### Scenario: 未完成问卷进入食养
- **WHEN** 用户未完成问卷就点到「食养」
- **THEN** 展示引导空态，点击按钮进入第 1 题

### Requirement: 我的页
「我的」SHALL 展示体质结果卡（体质名 + 描述 + 「食养参考」标签）、画像摘要（默认折叠，展开后用 Markdown 渲染）、问卷信息摘要（年龄段 / 饮食偏好 / 忌口，未提供显示「未提供」）、「重新填写问卷」与「查看完整画像」入口。

#### Scenario: 查看画像
- **WHEN** 用户在「我的」点「查看完整画像」
- **THEN** 进入画像二级页，可确认或重新填写

### Requirement: 跨端一致
Windows 端 SHALL 提供同名的三个 Tab、同字段菜谱卡、同 CTA 规则与同空态文案；体质计算、节气切换、菜谱筛选、忌口规则、免责声明与 Android 完全一致。

#### Scenario: 结果一致
- **WHEN** 两端输入相同的问卷答案并选择同一节气
- **THEN** 体质结果与推荐的 3 道菜名称一致

## MODIFIED Requirements

### Requirement: 问候
启动后不再有独立问候屏；固定问候语 SHALL 在首页问候卡内完整展示（文案不改）。首页主按钮进入问卷第一题。

#### Scenario: 启动
- **WHEN** 应用启动
- **THEN** 首页可见完整问候语与「开始健康问卷」按钮

### Requirement: 推荐正文排版
推荐结果 SHALL 以 3 张卡片 + 卡片间 12dp 间距呈现；卡片内字段用纯文本 + 图标/标签表达，不使用整段 Markdown；免责声明固定置于推荐区底部，字号 18sp、颜色 `#74685A`。画像摘要继续使用 Markdown 渲染。

#### Scenario: 推荐展示
- **WHEN** 推荐生成完成
- **THEN** 看到 3 张字段清晰的卡片与底部免责声明，无原始标记外露

### Requirement: 重新开始问卷入口
首页（已有结果时）、食养空态、我的页、问卷页与画像页 SHALL 提供「重新填写 / 重新开始问卷」入口，点击后清空本轮答案与结果并回到第 1 题；生成中的旧请求结果不得覆盖新页面（沿用既有 generation 机制）。

#### Scenario: 生成中重开
- **WHEN** 推荐生成中在任意入口点「重新填写问卷」
- **THEN** 回到第 1 题，旧结果不覆盖新页面

## REMOVED Requirements

### Requirement: 独立问候屏（Android `Screen.GREETING`）
**Reason**: 问候并入首页，避免多一次无信息量的点击。
**Migration**: 问候文案与品牌信息在首页完整保留，主 CTA 直接进入问卷。

### Requirement: 独立推荐屏（Android `Screen.RECOMMEND` 单页整段文本）
**Reason**: 推荐并入「食养」Tab，并改为结构化卡片。
**Migration**: 节气切换、重新推荐、重新开始问卷等能力在食养 Tab 内保留。
