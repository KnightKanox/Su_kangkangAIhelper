# 康康食养AI 独立桌面/安卓版 Spec

## Why
把 `Healthy_profiling-draft.yaml`（扣子 chatflow）的对话效果，落地为**可独立运行、不依赖扣子平台**的 Windows 桌面程序（.exe）与 Android 应用（APK），面向广州市海珠区社区老人，用 7 道题采集体质、年龄段和饮食信息，结合 24 节气从 288 道粤菜三系菜谱中推荐 3 道时令菜。Android 最低支持 Android 12（API 31），当前编译和目标版本为 Android 16（API 36）。

## What Changes
- 新建两个独立工程目录：`windows-app/`（Python + PyInstaller → 单文件 .exe）与 `android-app/`（Kotlin + Gradle → APK，minSdk 31 即 Android 12）。
- 复刻原工作流完整链路：问候 → 体质问卷 → 体质计算（九种体质）→ 画像确认 → 节气菜谱推荐。
- 用 DeepSeek（OpenAI 兼容接口）替代原「豆包」大模型；Windows 运行时、Android 构建时从 `DEEPSEEK_API_KEY` 环境变量读取密钥。未配置时使用本地回退文案。
- 菜谱数据采用 `12/02_菜谱资料/三系菜谱总表_288道.csv`，本地打包进两个程序，三系（广府/潮汕/客家）混合推荐。
- 界面形态「两者结合」：问卷用大按钮表单，画像摘要与菜谱推荐用对话式展示。
- 仅普通话话术。
- 节气「自动按当前日期为主 + 可手动切换」。
- 分发「最简」：Windows 单文件 exe + Android 可直接安装的 APK。
- 两端均支持重新开始问卷，生成的画像和推荐文案支持常见 Markdown 排版。

## Impact
- Affected specs: 体质采集（constitution-profiling）、节气菜谱推荐（seasonal-recipe-recommendation）、画像摘要（profile-summary）。
- Affected code（新增）:
  - `windows-app/`（Python：问卷 UI、体质计算、菜谱筛选、DeepSeek 调用、节气计算、PyInstaller 打包）
  - `android-app/`（Kotlin：同逻辑的 Compose 原生实现、assets 内嵌菜谱 CSV、APK 构建）
  - 共享数据：`12/02_菜谱资料/三系菜谱总表_288道.csv`（复制进两个工程）

## ADDED Requirements

### Requirement: 体质问卷采集
系统 SHALL 依次向用户提问并采集，全部为普通话；单选题用大按钮展示，开放题用文本框输入：
1. 怕冷怕热（怕冷/怕热/正常/冷热都怕）
2. 容易出汗吗（容易出汗/很少出汗/正常/晚上睡觉出汗）
3. 平时口干吗（经常口干/很少口干/正常/口苦）
4. 大便情况（偏软不成形/偏干硬/正常/时干时稀）
5. 年龄段（60岁以下/60—69岁/70—79岁/80岁及以上）
6. 饮食偏好（开放式文本）
7. 忌口食物（开放式文本）

#### Scenario: 正常完成问卷
- **WHEN** 用户依次选择/输入 7 个问题
- **THEN** 系统记录全部答案并进入体质计算

#### Scenario: 开放式问题留空
- **WHEN** 用户在「饮食偏好」或「忌口」留空
- **THEN** 系统按「无」处理，不阻塞流程

### Requirement: 九种体质计算（规则，本地确定性）
系统 SHALL 按固定映射与加权规则计算体质，结果取最高分，<4 分判「平和」，同分按优先级「阳虚>气郁>气虚>阴虚>湿热>痰湿>血瘀>特禀>平和」取其一。映射与分值**必须与原 YAML 代码节点 `1358364` 完全一致**：
- 怕冷=A、怕热=B、正常=C、冷热都怕=D
- 容易出汗=A、很少出汗=B、正常=C、晚上睡觉出汗=D
- 经常口干=A、很少口干=B、正常=C、口苦=D
- 偏软不成形=A、偏干硬=B、正常=C、时干时稀=D
- 分值权重（Q1 怕冷→阳虚+5；怕热→阴虚+3/湿热+2；正常→平和+2；冷热都怕→气虚+2/阳虚+2；Q2 易出汗→气虚+4/阳虚+2；少出汗→阳虚+3/血瘀+2；正常→平和+2；夜间盗汗→阴虚+4；Q3 常口干→阳虚+4(若Q1=怕冷)否则阴虚+4/湿热+2；少口干→平和+2/痰湿+1；正常→平和+2；口苦→湿热+3/气郁+2；Q4 软不成形→气虚+2/阳虚+2/痰湿+3；干硬→阴虚+3/湿热+1；正常→平和+2；时干时稀→气郁+4/气虚+2）。
- 每类体质输出对应的 `physique_desc` 话术（原 `desc_map` 文案）。

#### Scenario: 识别出明确体质
- **WHEN** 用户答案为「怕冷/容易出汗/常口干/软不成形」
- **THEN** 体质判为「阳虚」，并返回对应 desc

#### Scenario: 无法识别答案
- **WHEN** 所有答案均未匹配任何选项
- **THEN** 体质返回「参数错误」，提示用户重新确认

### Requirement: 健康画像摘要（LLM）
系统 SHALL 调用 DeepSeek 生成通俗、亲切、2–3 小段的画像摘要，顺序为「体质结果 → 年龄段与饮食偏好、忌口 → 身体状态」。年龄段只用于说明用户提供的信息，不用于疾病推断或更改本地体质计算。不得编造用户未提供的信息。若 LLM 调用失败，回退为包含体质、年龄段、偏好、忌口和四项身体状态的本地摘要。

#### Scenario: 生成摘要
- **WHEN** 体质计算完成且 LLM 可用
- **THEN** 展示含体质、年龄段、偏好、忌口的摘要

#### Scenario: LLM 失败降级
- **WHEN** 网络不可用或 API 报错
- **THEN** 用本地模板生成摘要，不阻塞

### Requirement: 画像确认与重新开始问卷
系统 SHALL 展示画像摘要并给「确认无误 / 重新开始问卷」两个选项；选「重新开始问卷」清空本轮答案并回到问卷第一题，选「确认无误」进入菜谱推荐。问卷每题和推荐页也提供「重新开始问卷」入口。画像或推荐尚在生成时，重新开始仍可使用，旧请求结果不得覆盖新页面。

#### Scenario: 确认无误
- **WHEN** 用户点「确认无误」
- **THEN** 进入节气菜谱推荐

#### Scenario: 重新开始问卷
- **WHEN** 用户在问卷、画像或推荐页点「重新开始问卷」
- **THEN** 清空答案并回到第一题

#### Scenario: 忽略旧请求
- **WHEN** 用户在生成过程中重新开始问卷或切换节气
- **THEN** 仅当前问卷或当前节气对应的结果可以更新页面

### Requirement: 节气确定（自动为主 + 手动切换）
系统 SHALL 默认按当前日期计算当前节气；界面提供入口手动切换到任意 24 节气之一。24 节气采用固定（月,日）近似表。

#### Scenario: 自动节气
- **WHEN** 程序启动或进入推荐
- **THEN** 按当天日期匹配节气

#### Scenario: 手动切换
- **WHEN** 用户手动选择某节气
- **THEN** 以所选节气作为推荐依据

### Requirement: 节气菜谱推荐（三系混合，本地筛选 + LLM 话术）
系统 SHALL 从 288 道菜谱中按「当前节气 + 体质宜忌 + 忌口」本地筛选，返回最多 3 道（不足则用临近节气补齐），再用 DeepSeek 生成通俗推荐话术（含免责声明「本推荐为食养参考，不构成医疗建议」）。年龄段和饮食偏好进入生成文案的提示词；年龄段不改变本地筛选规则。LLM 失败时回退为菜名+菜系+主料+做法的纯文本列表。

#### Scenario: 正常推荐 3 道
- **WHEN** 体质+节气+忌口确定
- **THEN** 返回 3 道符合节气与体质、且避开忌口的菜谱

#### Scenario: 忌口命中
- **WHEN** 用户忌口包含某食材
- **THEN** 该食材相关的菜谱被排除或降权

### Requirement: 问候（固定普通话）
系统 SHALL 在启动时展示固定普通话问候：「您好！欢迎使用康康食养AI，我是你的社区营养助手。接下来我会问你几个简单问题，了解你的身体状况，之后结合节气为你推荐合适的膳食。我们现在开始啦！」

#### Scenario: 启动问候
- **WHEN** 程序启动
- **THEN** 展示上述固定问候并进入问卷

### Requirement: 安全边界
推荐文案 SHALL 附带「本推荐为食养参考，不构成医疗建议」，不提供医疗诊断或用药建议。画像摘要展示问卷信息，不作为诊断。

### Requirement: 生成文案排版
画像摘要和菜谱推荐 SHALL 将常见 Markdown 标记排版显示，至少包括标题、加粗、强调和列表；不应把 `**` 等标记原样展示给用户。两端支持的边缘语法可能有差异。

### Requirement: 打包产物
- Windows：PyInstaller 生成**单文件** `KangKangShiYangAI.exe`（双击即用）。
- Android：Gradle 生成可安装 APK，`minSdkVersion 31`（Android 12+），`compileSdk` / `targetSdk` 36（Android 16）。

#### Scenario: 分发
- **WHEN** 用户拿到 exe 或 APK
- **THEN** 双击 exe / 安装 APK 后即可运行完整流程
